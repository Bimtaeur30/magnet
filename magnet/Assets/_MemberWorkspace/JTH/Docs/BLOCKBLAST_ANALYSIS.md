# Block Blast 인게임 사진 분석 — 스폰 알고리즘 역설계 기록

> **목적:** 실제 Block Blast 스크린샷을 턴 단위로 분석해 "왜 이 상황에서 이 3블록을 줬는가"를 역설계하고,
> 우리 `block-selection-algorithm`과의 차이를 찾아 개선한다.
> **작성 방식:** 사진이 들어올 때마다 §4 관찰 로그에 기록 → 표본이 쌓이면 §5 결론 갱신 → 코드 반영은 phase 문서로.

---

## 1. 분석 관점 (사진마다 보는 것)

| 관점 | 질문 |
|------|------|
| **모양 카탈로그** | 어떤 모양이 존재하는가? 대각선류가 있는가? 회전 변형이 따로 나오는가? |
| **패 구성 (번들)** | 3개가 세트로 의미가 있는가 (크기 조합, 상호보완)? 같은 모양 중복이 나오는가? |
| **보드 상태 연동** | 빈 곳/포켓/한 칸 부족 줄과 패가 맞물리는가? "쏙 들어가는" 블록이 오는가? |
| **점수·콤보 연동** | 점수가 오르면 패가 어려워지는가? 콤보 중엔 클리어 가능한 패가 유지되는가? |
| **기분 좋은 패** | 멀티라인·올클 기회를 주는 패가 얼마나 자주 오는가? 어떤 상황에서 오는가? |
| **응징/함정** | 못 놓는 패, 콤보 끊는 패가 실제로 존재하는가? 어떤 조건에서? |

## 2. 사전 가설 (공개 자료 조사, 2026-08-01)

> 출처: 커뮤니티 역설계·패턴 로깅 글 (blastblocksgame.com, pixelnitro.com 등 — 공식 아님, 사진으로 검증 필요)

- **H1. 가중 확률 + 보드 상태 연동**: 순수 랜덤이 아니라 빈 공간 형태가 다음 모양 확률에 영향.
- **H2. 점수 기반 난이도 곡선**: 점수가 오를수록 크고 어려운 모양 비중 증가 (3000~4000점 벽 보고 다수). ⚠️ **우리는 설계상 점수를 입력에서 제외** — 최대 격차 후보.
- **H3. Pity timer / 해결 블록**: 어려운 패 연속 후 쉬운 패 확률 급증. 15턴 무클리어 시 "해결 블록" 확률 대폭 상승. (우리의 Easy·Hospitality와 유사하나 우리는 blame 기반, 저쪽은 "고생 시간" 기반으로 추정)
- **H4. 백(bag) 시스템 + 메모리**: 7~10 모양을 백에 넣고 순차 드로우 → 특정 모양(1x4 등) 장기 가뭄 방지. 15~20피스마다 백 구성이 보드 상태로 재조정. (우리는 매 턴 독립 추첨 — 가뭄 방지 장치 없음)
- **H5. 콤보 후 시험**: 긴 콤보·클리어 연속 후 어색한 모양(S/Z 연속 등) 시퀀스로 "시험". (우리 ComboBreak과 유사)
- **H6. 대각선 블록 없음**: 공개 자료·플레이 영상에서 대각선(체스 비숍형) 모양 확인 안 됨. ⚠️ 우리 Diag2·Diag3는 오리지널에 없는 모양일 가능성 높음 — 사진으로 확정할 것.

## 3. 우리 알고리즘 현황 (비교 기준, phase8 시점)

- 티어 스택: Relife → Trap → ComboBreak → Hospitality → Easy → Pressure → Normal(Health 지향) → Fallback
- 입력: BoardHealth(채움·dead zone·큰 슬롯·자유도·클러스터) + Blame. **점수·콤보·턴 수는 입력 아님.**
- Normal 번들 10종 (mix/long/lines/big/bigL/bigthree/corner/diag/tetro/zigzag), 쏙 맞춤 부스트, 대각선·1x3 하향 (sequence8).
- 모양 17종 (1x1~1x5, 2x2, 3x2, 3x3, L3, L3x3, L4/J4/S4/T4/Z4, Diag2, Diag3).

## 4. 관찰 로그 (2026-08-01 · 프레임 954~1656, 344장 전수 분석)

> 한 세션 녹화 프레임 (점수 0 → 112,012 + 중간 게임오버·재시작 수회 포함).
> 10개 분석 에이전트가 구간별 전수 판독 — 아래는 구간 요약.

| 구간 | 점수대 | 핵심 관찰 |
|------|--------|----------|
| 954~1038 | 0~수만 | 시작 직후 소형 지그재그 위주. 콤보(보석 연출) 구간에서 **3x3 중복(×2) 핸드 8회 반복** |
| 1040~1108 | ~수만 | 3x3 중복 쌍 반복. 보드 빽빽해지면 얇은 1xN 지급 정황. 콤보로 프레임당 +5,768 등 폭증 |
| 1110~1178 | ~수만 | **3x3 트리플(×3)** 등장. 빈 보드→대형 직사각형, 고밀도→소형(1x1 포함) 매칭 경향 |
| 1180~1248 | 44k~71k → 새 게임 | 대각선 0. 중복 다수(1x4×2, Z4×2, **L3×3**, 1x3×2, 2x2×2, 3x3×2, 2x3×2). **배치 점수 = 칸 수(1점/칸)** 확인. 새 게임은 **보드 프리필(~45%)** 시작 |
| 1250~1318 | — | **[3x3, 3x3, 2x2] 핸드가 4회 재등장** (세트 템플릿 의심). 새 게임 프리필 ~60%. 큰 클리어 직후 대형 조각 지급 |
| 1320~1388 | — | 3x3 중복 빈번. 빈 보드 직후 대형 조각 집중. 동일 핸드 반복(1342/1346) |
| 1390~1458 | — | 고밀도 보드에서 라인·소형 조각 비중 상승(구제). All Clear 관찰. 점수 리셋+프리필 확인 |
| 1460~1528 | — | L3/1x4/3x3 중복 잦음. **고밀도에서 지그재그-only 핸드 직후 게임오버** (함정성 핸드 존재 정황) |
| 1530~1598 | 1.5k→57k | 초대형 콤보 스트릭 구간. **3x3 트리플 세트 3회 반복** — 콤보 중 큼직한 패 계속 지급 |
| 1600~1656 | 57k~112k | 중복 지급 4회(1x4×2, 3x3×2, L3×3). 밀도 역상관 유지. "Amazing!" 스트릭 +12K |

**전 구간 공통 (강한 신호):**

1. **대각선 조각 0건 / 344프레임** — Diag2·Diag3는 오리지널에 존재하지 않음 (H6 확정).
2. **한 핸드 내 같은 모양 중복이 매우 흔함** — ×2는 일상, ×3도 반복 관찰. 특히 [3x3,3x3,2x2] 같은 세트가 재등장 → 세트(번들) 추첨 + 중복 허용.
3. **콤보 흐름 중 큼직한 사각(3x3·2x2·직사각) 패 지급** — 이것이 "기분 좋은 패"의 정체. 클리어가 이어지는 동안 크고 시원한 조각을 계속 줘서 폭발 득점 유도.
4. **밀도 역상관** — 빈 보드엔 대형, 빽빽한 보드엔 얇은 조각(1xN·소형) 지급 (구제).
5. **점수 자체보다 보드 밀도·클리어 흐름이 지배 변수** — 고점수 구간의 소형 조각은 밀도 상승과 동행. (H2의 "점수 직접 입력"은 미확정 — 밀도로 설명 가능)
6. 새 게임은 **프리셋 프리필 보드(45~60%)**로 시작 (우리는 빈 보드 시작 — 스폰 알고리즘 밖 이슈).
7. 배치 점수 = 놓은 칸 수 1:1 + 콤보/클리어 배수 (score-logic 참고용).
8. 고밀도에서 지그재그-only 어려운 핸드 → 게임오버 사례 존재 (Trap 유사물 존재 정황, 빈도는 낮음).

## 5. 결론 → 반영 매핑 (phase9, 2026-08-01 반영 완료)

| # | 관찰 | 우리 알고리즘 반영 |
|---|------|-------------------|
| 1 | 대각선 없음 | Diag2·Diag3 전 티어 가중 0 + `normal_diag` 풀 제외 + `normal_corner`·`cb_smallmix`에서 교체 |
| 2 | 3x3이 매우 흔함 | 3x3 normal 가중 6→14, 3x2 12→14 |
| 3 | 핸드 내 중복 흔함 + 조합 다양성 | **Normal·Easy 티어를 고정 번들 → 모양 가중표 슬롯 독립 추첨(중복 허용)으로 전면 교체** — 실게임과 동일한 생성 모델. `normal_*` 번들 13종 삭제, 번들은 특수 티어(Trap·ComboBreak·Relife·Momentum) 전용 |
| 4 | 콤보 중 큼직한 패 | **Momentum 티어 신설** (Hospitality 다음): 직전 턴 클리어 발생 + TooDirty 아님 + 확률 60% → 큼직한 사각 번들(`mom_bigsquares`·`mom_squarefeast`·`mom_bigtriple`·`mom_rects`) |
| 5 | 밀도 역상관 | **밀도 바이어스**: fillRate>0.45면 얇은 블록 포함 번들 ×2, fillRate<0.25면 큰 블록 포함 번들 ×1.5 (Normal·Easy·Momentum 추첨) |
| 6 | 프리필 시작 | 구현 후 **사용자 결정으로 제거** (sequence9 #10~#15) — 빈 보드 시작 유지. 파생 기능 `DenseBigPenalty`(빽빽할 때 큰 블록 감점)만 존치 |
| 7 | 점수=칸수+콤보 배수 | score-logic 소관 — 참고 전달 |
| 8 | 함정 핸드 저빈도 존재 | 기존 Trap 티어 유지 (0.8%) — 변경 없음 |

**우리와 실게임의 남은 구조 차이 (후속 후보):**

- 백(bag) 기반 가뭄 방지 없음 (동일 모양 장기 미등장 가능) — 필요 시 "최근 N턴 미등장 모양 가중 보정" 추가.
- 실게임은 핸드 방향(회전)이 고정 노출 — 우리는 번들 추첨 후 랜덤 회전. 쏙 맞춤 랭킹이 회전 불일치를 걸러주지만, 완전 재현하려면 회전 지정 번들 필요.
- Hospitality/Fallback 실시간 생성 티어에는 밀도·쏙 부스트 미적용.

## 6. 사진 수집 가이드 (요청)

분석 정확도를 위해 이렇게 찍어주면 최고:

1. **연속 턴** — 같은 판의 리필을 연속으로 (배치 전 패가 보이는 화면). "직전에 뭘 했더니 뭘 줬다"가 핵심 데이터.
2. **점수 표시 포함** — 점수·콤보 연동 검증용 (H2·H5).
3. **다양한 국면** — 초반 빈 보드 / 중반 / 위기(꽉 참) / 콤보 중 / 게임오버 직전.
4. 한 메시지에 여러 장 첨부 가능. 순서대로 붙여주면 턴 순서로 간주.
